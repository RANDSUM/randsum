RANDSUM's zero-install web surfaces are the **RANDSUM API** at
`https://api.randsum.dev/v1` and the hosted games meta-schema. Both are public,
keyless and CORS-enabled, so you can call them from any browser, editor, agent
or server.

## RANDSUM API (`api.randsum.dev/v1`)

Every endpoint takes query parameters on `GET`, or the same fields as a JSON
object on `POST`, and answers with JSON. `GET https://api.randsum.dev/v1` lists
them all.

| Endpoint                     | Methods     | Does                                                           |
| ---------------------------- | ----------- | -------------------------------------------------------------- |
| `/v1/roll`                   | GET, POST   | Roll [RANDSUM notation](/spec/); optional integer `seed`        |
| `/v1/validate`               | GET, POST   | Check notation without rolling                                 |
| `/v1/random`                 | GET         | Uniform random integers from `min` to `max` (cryptographic)     |
| `/v1/games`                  | GET         | List supported game systems and the inputs each takes          |
| `/v1/games/{game}/roll`      | GET, POST   | Roll for a game system, interpreted by its rules               |

The same engine is also served as an MCP server at
`https://api.randsum.dev/mcp`, for AI agents and Claude connectors. See
[MCP Server](/tools/mcp/).

### Roll notation

```bash
curl "https://api.randsum.dev/v1/roll?notation=4d6L"
```

```json
{
  "notation": "4d6L",
  "total": 14,
  "pools": [
    {
      "notation": "4d6L",
      "rolls": [3, 5, 6],
      "total": 14,
      "description": "Roll 4 6-sided dice, Drop lowest"
    }
  ],
  "description": "Roll 4 6-sided dice, Drop lowest"
}
```

URL-encode the notation in a query string (`2d20H+5` is `2d20H%2B5`), or `POST`
it instead:

```bash
curl -X POST https://api.randsum.dev/v1/roll \
  -H "Content-Type: application/json" \
  -d '{"notation":"2d20H+5","seed":42}'
```

A `seed` makes the roll reproducible: the same notation and seed always give the
same dice.

### Validate notation

```bash
curl "https://api.randsum.dev/v1/validate?notation=4d6L"
```

Returns `valid`, plus a `description` when valid, or an `error` and often a
`suggestion` when not. Validation itself always answers `200`.

### Random integers

```bash
curl "https://api.randsum.dev/v1/random?min=1&max=6&count=3"
```

```json
{ "min": 1, "max": 6, "count": 3, "values": [4, 1, 6] }
```

`min` defaults to 1, `max` to 100 and `count` to 1. Values come from
`crypto.getRandomValues` with rejection sampling, so every integer in the range
is equally likely. A request may ask for up to 1000 values over a range of up
to 2³² integers.

### Game systems

```bash
curl "https://api.randsum.dev/v1/games/blades/roll?rating=3"
curl -X POST https://api.randsum.dev/v1/games/fifth/roll \
  -H "Content-Type: application/json" \
  -d '{"modifier":5,"rollingWith":"Advantage"}'
```

```json
{ "game": "blades", "total": 6, "result": "success", "rolls": [6] }
```

`{game}` is one of `blades`, `daggerheart`, `fate`, `fifth`, `pbta`,
`root-rpg` or `salvageunion`. `GET /v1/games` lists each game's inputs, with
their types, bounds and defaults, straight from its spec.

### Errors and limits

Bad input answers `400` with an `error` naming the problem, plus a `suggestion`
for notation the roller can guess a fix for. An unknown game or route is a
`404`; a body over 4 KB is a `413`. Each client IP may make about 120 requests a
minute; past that the API answers `429` with `Retry-After: 60`. Responses that
roll or draw are sent with `Cache-Control: no-store`.

## Hosted meta-schema

The `@randsum/games` package validates every `*.randsum.json` game spec against a
[JSON Schema](https://json-schema.org). That schema is published at its declared
`$id`:

```
https://randsum.dev/schemas/v1/randsum.json
```

It is served as `application/json` and is byte-identical to the source of truth
in the monorepo (`packages/games/randsum.json`) — a build step copies it into the
site and a sync test fails the build if the two ever drift.

### Editor autocompletion

Until the schema lands in [SchemaStore](https://www.schemastore.org) (tracked in
[issue #1130](https://github.com/RANDSUM/randsum/issues/1130)), reference it
explicitly with a `$schema` key so editors like VS Code give you completion and
validation while authoring a game spec:

```json
{
  "$schema": "https://randsum.dev/schemas/v1/randsum.json",
  "name": "My Game",
  "shortcode": "mygame",
  "game_url": "https://example.com",
  "roll": {
    "dice": { "pool": { "sides": 6, "quantity": 2 } },
    "resolve": "sum"
  }
}
```

## `POST randsum.dev/api/roll`

The original single endpoint, still served by the site. New integrations should
use [`/v1/roll`](#roll-notation) above, which adds seeds, per-pool results and
`GET`. This one evaluates [RANDSUM dice notation](/spec/) with the same
`roll()` engine as `@randsum/roller`.

### Request

`POST` JSON with a single `notation` field:

```bash
curl -X POST https://randsum.dev/api/roll \
  -H "Content-Type: application/json" \
  -d '{"notation":"4d6L"}'
```

### Response — `200 OK`

```json
{
  "notation": "4d6L",
  "total": 12,
  "rolls": [3, 4, 5],
  "description": "Roll 4 6-sided dice; Drop lowest"
}
```

| Field         | Type       | Description                                  |
| ------------- | ---------- | -------------------------------------------- |
| `notation`    | `string`   | The notation that was rolled                 |
| `total`       | `number`   | Combined total of all rolls                  |
| `rolls`       | `number[]` | Individual die values after modifiers        |
| `description` | `string`   | Human-readable description of the roll        |

### Errors — `400 Bad Request`

Invalid notation returns the roller's own error message, plus a `suggestion`
when a likely fix can be inferred (the same hint powered by `suggestNotationFix`):

```bash
curl -X POST https://randsum.dev/api/roll \
  -H "Content-Type: application/json" \
  -d '{"notation":"d6"}'
```

```json
{
  "error": "Invalid dice notation: \"d6\"",
  "suggestion": "1d6"
}
```

Notation longer than 1000 characters is rejected before parsing, and oversized
request bodies return `413 Payload Too Large`.

### Usage — `GET /api/roll`

A plain `GET` returns a JSON description of the contract, handy for quick
discovery:

```bash
curl https://randsum.dev/api/roll
```

### CORS

Every response includes `Access-Control-Allow-Origin: *`, so the endpoint is
callable directly from browser front-ends.
