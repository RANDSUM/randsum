Roll dice for D&D 5e, Blades in the Dark, Daggerheart, Fate Core, PbtA, Root RPG and Salvage Union with typed, game-specific functions. Each game validates input, rolls using the core engine, and interprets the result according to that system's rules.

Every game runs on `@randsum/roller`, which implements the full [RANDSUM Dice Notation (RDN) Specification](https://notation.randsum.dev/).

## How they work

Every game follows a three-step pipeline: validate input, roll dice, interpret the result.

<CodeExample code={`import { roll } from '@randsum/games/salvageunion'

// 1. Validate: checks that the table name matches a known table
// 2. Roll: rolls the d20 with @randsum/roller
// 3. Interpret: looks up the result in that table by range
const result = roll('Core Mechanic')

console.log(result.result.label)       // 'Nailed it' | 'Success' | 'Tough Choice' | ...
console.log(result.result.description) // full outcome text
console.log(result.total)              // d20 roll
console.log(result.rolls)              // raw RollRecord[] from the roller`} />

## Common patterns

Every game shares these characteristics:

- **One `roll()` function**: each subpath exports `roll()` as its main API, plus its `inputs` schema and `SchemaError`
- **Game-specific input types**: typed input, not raw notation strings
- **`GameRollResult` return type**: includes `result` (the game outcome), `total`, `rolls`, and optional `details`
- **Input validation**: throws `ValidationError` (from roller) for out-of-range numeric input and `SchemaError` for game-specific issues like invalid enum values or unmatched outcome tables
- **No cross-dependencies**: games depend only on `@randsum/roller`, never on each other
- **Small subpath imports**: each game bundles only its own rules, with a size budget checked in CI

## Quick comparison

| Game | Dice | Input | Outcomes |
|---|---|---|---|
| `salvageunion` | 1d20 | `tableName` (string) | Table result with label + description |
| `fifth` | 1d20 or 2d20 | `modifier`, `rollingWith`, `crit` | Numeric total |
| `fate` | 4dF | `modifier` (skill rating, -2 to 5) | A Fate ladder rung, `terrible` to `legendary` |
| `blades` | Nd6 pool | `rating` (number, 0-10) | `critical`, `success`, `partial`, `failure` |
| `pbta` | 2d6 | `stat`, `forward`, `ongoing`, `rollingWith` | `strong_hit`, `weak_hit`, `miss` |
| `daggerheart` | Hope/Fear dice | `modifier`, `amplifyHope`, `amplifyFear`, `rollingWith` | `critical_hope`, `hope`, `fear` |
| `root-rpg` | 2d6 | `bonus`, `rollingWith` | `strong_hit`, `weak_hit`, `miss` |

## Installation

Install `@randsum/games` once, then import the game you need via subpath exports. This also installs `@randsum/roller` as a dependency.

<CodeExample lang="bash" code={`bun add @randsum/games`} />

<CodeExample code={`import { roll } from '@randsum/games/salvageunion'
import { roll } from '@randsum/games/fifth'
import { roll } from '@randsum/games/blades'
import { roll } from '@randsum/games/pbta'
import { roll } from '@randsum/games/daggerheart'
import { roll } from '@randsum/games/fate'
import { roll } from '@randsum/games/root-rpg'`} />

<Aside type="note" title="Games are data, not code">
Every game is code-generated from a `.randsum.json` spec, a declarative description of the game's dice mechanics, input validation, and outcome interpretation. The TypeScript you import is produced by a build-time codegen pipeline, not hand-written. See the [Schema Overview](/games/schema/overview/) for how this works.
</Aside>
