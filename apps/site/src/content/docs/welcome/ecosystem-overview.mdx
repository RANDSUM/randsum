RANDSUM is one dice engine with several ways in. Two npm packages hold the code, an open spec defines the notation, and the API, Discord bot, agent plugin and Roller app put the same engine in front of people who are not writing TypeScript. Every package ships ESM with full type declarations and is published to npm under `@randsum`.

## Dependency diagram

```
@randsum/roller              (zero dependencies, includes the notation parser)
  |
  +-- @randsum/games         (one package, a subpath per game)
  |     +-- /blades            (Blades in the Dark)
  |     +-- /daggerheart       (Daggerheart)
  |     +-- /fate              (Fate Core)
  |     +-- /fifth             (D&D 5e)
  |     +-- /pbta              (Powered by the Apocalypse)
  |     +-- /root-rpg          (Root RPG)
  |     +-- /salvageunion      (Salvage Union)
  |
  +-- @randsum/mcp           (MCP server: roll, validate, roll_game)
```

Every package depends only on packages above it in the tree. Games never depend on each other.

## Where to start

Pick the one that matches your use case:

| Use case | Install | Start here |
|---|---|---|
| **Roll dice in any JS/TS project** | `bun add @randsum/roller` | [Roller Getting Started](/roller/getting-started/) |
| **Parse or validate notation strings** | `bun add @randsum/roller` | [Notation Getting Started](/notation/getting-started/) |
| **Build a TTRPG app with game-specific mechanics** | `bun add @randsum/games` | [Games Getting Started](/games/getting-started/) |
| **Roll from another language or a no-code tool** | nothing | [RANDSUM API](/api/introduction/) |
| **Give an AI agent dice** | the plugin or connector | [Dice for AI Agents](/tools/agents/) |

Most developers should start with `@randsum/roller`. It includes the full notation parser and validator along with all rolling functionality and types.

## Design principles

- **RDN conformant**: `@randsum/roller` implements the [RANDSUM Dice Notation (RDN) Specification](/spec/) at Level 3 (Extended) conformance
- **Zero core dependencies**: `@randsum/roller` has no runtime dependencies and includes the full notation parser and validator
- **Throws on invalid input**: `roll()` throws typed errors on bad input (`ValidationError`, `ModifierError`, or `NotationParseError`); validate user-provided strings with `isDiceNotation()` or `validateNotation()` before rolling
- **Games are code-generated**: every game is a `.randsum.json` spec compiled into TypeScript by the games package's codegen
- **Strict TypeScript**: `isolatedDeclarations`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, no `any`
- **Bundle size enforced**: every roller and games entry point has a size budget checked in CI by size-limit; the budgets live in each package's size-limit config (`packages/roller/package.json`, `packages/games/.size-limit.ts`)
